# 数据集版本对比与交付

[English](RELEASES.md) · [演示导览](DEMO.md)

从 **数据库 → 数据集 → 版本** 选择同一数据集的两个版本，点击 **对比版本**。五类结果为新增、删除、内容变更（SHA-256 改变）、仅元数据变更、未变。每类显示完整计数，文件清单分页加载，同时展示标注数、标签数、文件质量分均值和证据决策统计的前后变化。质量分按版本摘要中登记的统计口径计算。

旧版本保留文件清单，但没有历史治理快照。对比质量分按数据集当前的质量配置计算；证据决策摘要使用各版本关联证据当前的活跃决策状态。

本地命令示例：

```bash
uv run datakeel version-diff DATASET_ID BEFORE_VERSION AFTER_VERSION --limit 50 --category content_changed --json
```

用 `--offset` 翻页；不指定 `--category` 时返回混合分类页。API 为 `GET /api/datasets/{dataset}/diff?before={version}&after={version}&offset=0&limit=50`，跨数据集的版本会被拒绝。文件按清单中的文件 ID 对齐：相同 ID 先比 SHA-256，再比元数据；具有新 ID 的派生产物算新文件。

## 发布与查看

在 **版本 → 发布版本** 选择来源版本，输入 `v1.2.0` 等语义化标签及发布说明，点击 **审阅发布计划**。检查冻结参数、文件影响、摘要和不可逆提示后，点击 **签批并发布版本**。准备计划不会发布；签批只适用于这一份冻结计划，待办也会出现在 **审批待办**。

修改来源版本、标签、说明或任一预算字段，会立即清掉表单下方的计划；须重新审阅计划后再签批修改后的表单。修改前发起的准备请求即使稍后返回，也不会恢复旧计划。服务端已准备的冻结计划仍可在 **审批待办** 中按原参数查看。

发布记录出现在列表中，文件数量显示为 **2 个文件**（英文为 **2 files**）。展开标签可查看来源版本、清单 SHA-256、说明、总字节数和分页冻结文件。发布冻结的是准备发布计划时的当前治理元数据、质量测量及证据决策摘要。发布后的文件、元数据和哈希均不可修改；后续修改须生成新版本并再次发布，原有生成版本流程保持兼容。

自动化继续使用受控动作协议：`POST /api/actions/publish_release/prepare`，参数为 `dataset_id`、`version_id`、`tag`、`notes`；随后在 `POST /api/approvals/{plan_id}` 签批，再通过 `POST /api/actions/{plan_id}/execute` 执行。签批和执行须携带返回的计划摘要，执行使用该计划的 operation ID。查询接口为 `GET /api/datasets/{dataset}/releases`、`GET /api/releases/{release}` 和 `GET /api/releases/{release}/files?offset=0&limit=50`。

### 大版本发布

受控动作每个计划默认最多 1 万个对象、10 GiB。发布和由证据选择生成版本会冻结整份清单，因此 `publish_release` 与 `create_version_from_selection` 可以显式申请更高预算。不申请时，超出默认值的计划会被拒绝，错误信息给出实测影响和申请方法。预算写在计划的 `context`（`max_objects`、`max_bytes`）中，受计划摘要保护，签批单上显示为「授权预算」；签批和执行时会再次用它核对冻结的影响。

- Web：在「发布版本」填写「最多文件数」和/或「最大容量（GiB）」，留空即用默认值。
- HTTP：`POST /api/actions/publish_release/prepare?max_objects=20000&max_bytes=2147483648`，请求体不变；其他动作类型带这两个参数会被拒绝。
- CLI：`uv run datakeel release-plan prepare publish_release params.json --max-objects 20000`，再执行 `release-plan approve PLAN_ID --digest DIGEST` 和 `release-plan execute PLAN_ID --digest DIGEST`。`params.json` 与 HTTP 请求体相同；`create_version_from_selection` 用法一样。

申请上限由 `DATAKEEL_RELEASE_BUDGET_MAX_OBJECTS`（默认 100 万）和 `DATAKEEL_RELEASE_BUDGET_MAX_BYTES`（默认 1 TiB）控制。超过上限的申请返回 `422`，错误信息写明这两个配置项。管理员若在准备计划后调低上限，显式预算已超限的计划不能再签批或执行；使用默认预算的计划不受影响。执行时仍会逐个读取并校验所有发布对象的哈希，发布越大耗时越长。

## 导出与离线对账

发布详情中的 **导出交付包** 下载 gzip tar 包。本地命令可导出压缩包或新目录：

```bash
uv run datakeel release-export RELEASE_ID --output delivery.tar.gz
uv run datakeel release-export RELEASE_ID --output delivery-directory
```

对应 HTTP 接口为 `POST /api/releases/{release_id}/export`，返回媒体类型为 `application/gzip` 的 tar 压缩包。归档是可复现的：成员按路径排序，属主和属组名为空、uid/gid 为 0、权限为 `0644`、修改时间为 0，gzip 头不含文件名和时间，因此同一发布重复导出得到逐字节相同的文件，也不会带出服务器的系统账户名。

交付包包含：

- `MANIFEST.json`：相对路径、字节数、SHA-256、媒体类型、来源版本、血缘引用、标注及标签数、元数据及必填字段，以及规范化清单哈希。
- `RECORDS.json`：收货侧独立核对的数据集元数据，以及逐文件元数据、标注及标签统计和血缘。
- `files/`：实际文件内容。

两个 JSON 文件须与文件内容一同交付。路径均为相对路径，不携带凭证或内部物理存储位置。元数据按字段角色和取值结构过滤：去掉声明为位置的字段（`path`、以 `path` 结尾的字段如 `source_path`、`object_key`、`storage_uri`）、凭证字段、`file://` 或 `s3://` 等存储 URI，以及带凭证的 URL；其他取值原样保留，以 `/` 开头的标签（如 `/m/01yrx`）不会被删除，也计入标签数。导出时根据 [contracts/delivery-manifest.schema.json](../contracts/delivery-manifest.schema.json) 校验清单。清单哈希用于发现清单损坏，不是证明发件人身份的数字签名；需要核验真实性时另行保留可信哈希副本。

文件路径使用序号目录及百分号编码后的文件名，过长编码名会缩短并附加摘要后缀。请按 `MANIFEST.json` 登记的原样路径核对，不要先解码或重命名。Web 中的来源发布快照哈希与交付清单规范化哈希覆盖不同序列化内容，不能互相替代。交付清单哈希使用对象键排序、紧凑分隔符及不转义 Unicode 的 UTF-8 JSON，仅排除顶层 `manifest_sha256` 字段，导出会写入 schema 默认值，对账按实际收到的字段计算，删除默认字段也会被发现；比较交付清单时须使用预期交付清单中的哈希。

收货方安装 Datakeel 后即可运行下列命令，无须连接 API、数据库、对象存储或模型服务：

```bash
datakeel reconcile delivery.tar.gz --manifest MANIFEST.json
datakeel reconcile delivery-directory --manifest MANIFEST.json --json
```

默认清单路径相对于交付包解析。人类输出包含中英文，`--json` 提供结构化报告。六类全通过时退出码为 `0`，发现差异时为 `1`，无法读取或校验交付包、清单时为 `2`。无效输入的 JSON 输出为 `error: "invalid_delivery"` 及错误类别 `reason`，不会回显输入内容。六类分别检查文件数；总字节数和逐文件大小；SHA-256；标注及标签数；必填元数据字段和取值；指向已登记来源版本的血缘引用。元数据及标注检查将 `RECORDS.json` 与 `MANIFEST.json` 对比，不会从任意媒体内容中推断标注语义；缺少收货记录会失败。

标注统计优先使用元数据中明确提供的非负整数 `annotation_count` 或 `label_count`；否则依次查看复数集合（`annotations`、`labels`）和单数集合（`annotation`、`label`）：列表取长度，存在的非空标量或对象计为一，没有登记值计为零。收货记录包含这些字段时还会核对由集合推得的统计与声明数量。明确的数量字段具有优先权，即使同时存在集合也不被覆盖；集合被改动仍会由元数据比较独立发现。

元数据检查覆盖数据集和文件字段、必填字段是否存在以及完整 JSON 值。对象键顺序不影响结果，数组顺序及标量表示影响结果，例如 `true`、`1`、`1.0` 和 `"1"` 不等同。若预期值也是 JSON `null`，必填字段允许取 `null`；此检查不附加业务上的非空约束。

故意破坏一个副本以验证发现差异的能力：

```bash
mkdir received
tar -xzf delivery.tar.gz -C received
python3 - <<'PY'
import json
from pathlib import Path

root = Path("received")
manifest = json.loads((root / "MANIFEST.json").read_text())
payload = root / manifest["files"][0]["path"]
with payload.open("r+b") as stream:
    first = stream.read(1)
    stream.seek(0)
    stream.write(bytes([first[0] ^ 1]) if first else b"x")
PY
datakeel reconcile received --manifest MANIFEST.json
```

哈希分类会指出文件路径和预期、实际值。非空文件只替换一个字节时长度不变，因此字节数分类仍通过。练习元数据、标注或血缘故障时，修改 `RECORDS.json` 对应记录，保留作为预期的原清单。

## 分片上传与断点续传

向 `POST /api/uploads` 提交 `idempotency_key`、`name`、`filename`、`total_bytes`、完整源文件的 `sha256`、`chunk_bytes` 和可选 `metadata`，保存返回的上传 ID。通过 `GET /api/uploads/{id}` 获取 `received_chunks` 和 `missing_chunks`，新客户端只补缺失分片。分片编号从零开始，通过 `PUT /api/uploads/{id}/chunks/{ordinal}` 发送精确大小的原始字节，设置 `Content-Type: application/octet-stream`。最后调用无请求体的 `POST /api/uploads/{id}/complete` 校验并导入；成功回执包含 `COMPLETE` 状态及 `dataset_id`。

相同分片重传会合并，内容冲突的重复分片会拒绝；允许乱序到达。同一上传的重叠写入返回 `409`，客户端可在前一写入完成后重试。同一个初始化幂等键恢复同一声明，修改声明返回 `409`；不同键代表独立导入意图。完成请求可重复调用。导入前检查整文件 SHA-256，提交数据集事务前再读回实际存储对象核对哈希。大小错误、缺片或哈希不符返回 `422`，不会创建数据集；不存在的上传 ID 返回 `404`。

初始化、分片写入或完成请求遇到上传锁忙时，返回 `409`，其 `detail` 为 `"Upload is busy; retry after the active upload operation completes"`（该上传正由其他操作占用，请稍后重试）。此文案明确指出上传操作；会话冲突保留原文案。全局上传写入并发名额用尽时，仍提示上传并发上限。

配置上限为 `DATAKEEL_UPLOAD_MAX_CHUNK_BYTES`（默认 8 MiB，最高 64 MiB）、`DATAKEEL_UPLOAD_MAX_CONCURRENCY`（默认 4，最高 32）和 `DATAKEEL_UPLOAD_MAX_FILE_BYTES`（默认 5 GiB，最高 1 TiB）。最多 100,000 个分片，选择分片大小时须满足这一限制；超出并发写入限制返回 `409`。

分片暂存于配置的 `DATAKEEL_HOME` 下的 `uploads/<上传 ID>/`。完成成功、数据集事务提交后，暂存分片立即删除；若进程恰好在提交后、删除前退出，再次调用完成接口会补做删除。未完成的上传，以及因缺片、大小或哈希不符而完成失败的上传，分片一直保留，以便续传或排查；本版没有放弃接口，也没有自动过期，需要清理时由运维删除对应目录。磁盘容量须覆盖未完成上传的分片及整文件临时组装。持久文件系统不变时，客户端或进程重启后仍可续传。多个 API 主机须共用暂存卷和数据库，或将同一上传固定路由至原主机；只共用 PostgreSQL 不会共享分片字节。进程锁防止重叠写入，不负责复制暂存文件。

使用 `npm --prefix web run smoke:release -- http://127.0.0.1:8816 OUTPUT_DIRECTORY` 重放发布浏览器流程：创建生成样本、对比两个版本、从界面签批发布、下载并核对交付包、修改一个字节，最后确认平台存档报告刷新后仍在。截图及结构化结果写入指定输出目录。脚本仅允许请求给定回环地址，要求浏览器零错误。

## v0.13.0 版本说明

v0.13.0 合入十二条已验收的功能线，并带两处发布相关修正。所有功能线沿用原有受控动作规则：修改先生成冻结计划，不可逆或外发的计划须人工签批，读取统一经过数据资产访问守卫。

| 功能线 | 现在能做什么 |
|---|---|
| 时序传感器与表格剖析 | 统一混用的时间戳格式，排序去重，找出采样断档、卡值、稳健离群、越界和单位不一致，并剖析表格列。带同样趋势、周期和噪声的干净对照数据不产生发现。问数可回答传感器剖析类问题。 |
| Rust 近重复加速 | 可选的原生扩展加速感知哈希近重复查找（10 万个聚簇哈希约快 400 倍），结果逐位相同；exact 模式还能找出只在前缀位不同的近重复。用 `DATAKEEL_ACCEL=auto|off|required` 选择实现。 |
| 自定义算子与安全沙箱 | 提交 Python 算子，在审批单上审阅代码和哈希，随后在容器中运行：无网络、根文件系统只读、非 root 用户、无 capability、启用 seccomp 过滤。输出只能是声明过的普通文件。 |
| 图片 auto 模式 | 每张图片自动选择 OCR 或视觉模型。视觉模型按声明的坐标空间（如 `normalized_1000`）给出的框会换算成像素；与 OCR 交叉核对不过的框整张丢弃并标 `coordinates_unreliable`，不会画错位置。 |
| 版本对比、发布与交付对账 | 按五类对比两个版本，签批后发布不可修改的发布版本，导出自带清单的交付包，在线下或平台侧对账，分片上传支持断点续传。 |
| 数据资产上架与访问申请 | 把数据集、表和指标上架为资产，分为公开、受限、需申请三种策略。用户申请查询或下载权限，授权可到期或撤销。问数、导出、下载、Agent 和 MCP 共用一个守卫，每次受管读取都留审计。 |
| 数据标准与落标 | 导入字段标准、码表和同义词，审阅系统建议的列映射，通过签批计划确认或回滚，并查看落标最差的表。 |
| 问数听懂率 | 英文指标问法与中文一样解析时间和筛选条件；泛称会先澄清而不是猜；工作流请求的召回提高，单纯询问工作流不会再启动它。 |
| 数据质量规则与监控 | 在 SQLite 或 PostgreSQL 表上定义非空、唯一、范围、枚举、正则、参照完整性、SQL 断言、量级变化、新鲜度和分布漂移规则。定时运行会开单、合并和恢复问题单，并发送 HMAC 签名的 webhook。SQL 断言只能调用白名单函数。 |
| dbt / Airflow / OpenLineage 元数据导入 | 把 dbt 的 manifest、run results、catalog，Airflow 导出和 OpenLineage 事件导入数据目录，带列级血缘。不带 `catalog.json` 重导会沿用上次的列；只重跑不改项目不再算变更；Airflow 数据集 URI 会挂到匹配的数据库来源。1000 个模型约 10 秒导完。 |
| 标注质量评估与抽检验收 | 计算一致性（Cohen / Fleiss κ、Krippendorff α、框 IoU 与片段匹配），按批次级离群阈值标出疑似错标，按 ISO 2859-1（AQL）或固定比例抽检，通过签批计划记录接收或拒收，并对比返工前后。 |
| 数据集说明书 | 为某个数据集版本生成七章中文或英文说明书，可用离线模板或已配置的模型。保留的每句话都引用冻结的平台事实；数字、日期、百分比或名称得不到被引用事实支持的句子会被删除，并列出原因。发布须签批；数据集有新版本后，旧说明书标为已过期。 |

两处发布相关修正：

- **大版本发布与生成版本。** 发布版本和「按选择生成版本」现在可以申请显式预算，上限可配置，默认 100 万个对象、1 TiB。申请的预算冻结在用户签批的计划里。见[大版本发布](#大版本发布)。
- **ICU 排序库上的版本对比。** PostgreSQL 上按码点排序文件 ID（`COLLATE "C"`），默认排序规则为 ICU 的库里，大小写混合或带连字符的 ID 也能正确归类。数据库若仍返回乱序，对比直接报错，不会错误归类。

v0.13.1 在 v0.13.0 之上合入两条已验收的功能线。两条线都只用本地工具，不调用模型服务，沿用 v0.13.0 的受控动作与访问守卫规则。

| 功能线 | 现在能做什么 |
|---|---|
| 音视频预处理 | 用自装的 `ffmpeg`/`ffprobe` 探测录制；找出黑屏、纯色、冻帧、模糊帧、重复画面、静音、削波、响度越界和重复音频；把同一事件的多路录制对齐；只在干净区间按固定窗口切片并归一；原始录制和切片一起保留，并带原始时间区间的血缘。长录制的超时随时长和分辨率放大；某条录制失败时记下算子和原因，其余照常完成；截断文件按文件头承诺的时长报出来。`demo-media` 可以跑合成录制，也可以跑自己的本地文件。 |
| 图片质量与点云 | 按模糊、曝光、噪声、分辨率、纯色给图片打分，并给出每项不合格的测量原因；探测 PLY/PCD 点云，判断单位是否存疑，清理无效坐标，按体素降采样，标出孤立点和分离点团这两类统计离群，同时保留被遮挡或远处的真实结构，并在文件对象页看俯视 PNG 预览。没有声明采集形式时稀疏只给提示，声明了才判定。读不了的图片或扫描记下原因，整批照常完成。 |

已知边界写在[音视频预处理说明](MEDIA.md)和[图片与点云质量](MEDIA_QUALITY.md)里。简单说：有损编码后的人声和音乐削波只能部分召回，适合当文件级提示而不是逐段地图；细纹理画面跨帧率可能认不出；位翻转的 TS 不会被标记；贴近真实结构的稀疏点团可能漏检；点云默认阈值只在生成扫描上校准过。

本版的集成改动：

- 质量评分按表格规则、图片与点云乘数、录制扣分的顺序叠加。质量视图只在测过录制时才带 `media` 汇总；图片和点云的观测放在各维度明细的 `image_pointcloud` 下，报告里各自成章。
- 图片与点云的预设流水线是 `datakeel.pipeline.image_pointcloud.image_pointcloud_pipeline()`；`datakeel.pipeline.media.media_pipeline()` 是音视频链。
- 点云预览下载和文件下载走同一个数据资产下载守卫。
- 血缘里已签批的自定义算子以代码哈希作为算子版本。

## v0.14.0 版本说明

v0.14.0 在 v0.13.1 之上合入两条已验收的功能线，并做一项全局加固。两条线都只用本地工具，不调用模型服务，沿用受控动作与访问守卫规则。

| 功能线 | 现在能做什么 |
|---|---|
| 大规模压测与容量基线 | 一条命令 `python -m scripts.scale_bench B1 --size M --stack sqlite --seed 23 --output result.json`（B1–B7、S/M/L、SQLite 或 PostgreSQL）得到一份 JSON：机器、提交、规模、夹具指纹、延迟、计数、峰值内存和清理状态；同一种子在两栈上生成同一份夹具。八条热路径改成有界读取（文件分页与全局检索、目录与血缘查询、冻结文件选择与对象投影、任务租约与终态读取、上传完成），`make check-scale` 在版本对比再次变成二次方时直接失败。[容量基线](CAPACITY.md)写明 M、L 两档测了什么、哪些目标达标哪些没有、什么时候该从 SQLite 换到 PostgreSQL。 |
| 问数出图表与多轮追问 | 每个问数答案都带一张按结果形状选出的图表，Web 页面用 SVG 画出来，键盘就能切到源表。可以在同一会话里接着问：`那华南呢`、`上个月呢`、`按渠道拆开`、`换成订单数`、`同比`、`what about South China`、`what about August 2026`；每一轮都显示「理解为」和完整问句，模糊的追问只澄清不出数，每一轮都重查资产授权。会话在 SQLite 和 PostgreSQL 上跨重启保留，可以列出、重开和删除，保留天数由 `DATAKEEL_ASK_CONVERSATION_RETENTION_DAYS` 决定（默认 30）。HTTP、CLI、Agent 工具和 MCP 共用同一个 `conversation_id`。 |

**签批只由人做。** MCP 服务不再列出 `approve_plan` 和 `execute_plan`，共 57 个工具：20 个只读函数、37 个只准备冻结计划的动作。经 MCP 以这两个名字调用会被拒绝并说明原因，记为一次失败调用；计划停在「已准备」，直到有人在 Web 界面或 CLI 签批并执行。这是对 MCP 客户端的行为变化——之前把签批写进脚本的客户端要把这一步挪到 CLI 或 Web；内置 Agent 本来就走 UI 确认流程。

已知边界写在[容量基线](CAPACITY.md)和[问数图表与追问](ASK.zh.md)里。简单说：M 档下 PostgreSQL 深分页、两栈的文件名+模态筛选、SQLite 全局检索、SQLite 在 B1 的峰值内存、深度 5 血缘和 50 用户 p95 都还高于目标，SQLite 上 B5 每约 1300 次请求出现一到两次 HTTP 500、原因尚未证实；目录搜索在加入转义 payload 检测后重测，两栈都变慢。问数方面，会话里一句完整的新问句（包括答不了的）会开新框架，之后的「那华南呢」指向新话题。

本版的集成改动：

- 媒体观测索引只解码带图片或点云测量的版本清单，默认文件投影不论版本多少都只读一份清单和一批文件状态。
- 会话里一句没有任何槽位能解释的疑问句（`why did brand awareness drop`）按新问句回答——无法回答并给出最接近的三个指标——而不是当成只有一个候选的追问。

## v0.15.0 版本说明

v0.15.0 在 v0.14.0 之上合入四条功能线和两批小修。都不调用模型服务：检查只用本地规则和统计，生产项目里的模型是假模型或离线导入的结果；所有写操作照旧走受控动作和访问守卫。

| 功能线 | 现在能做什么 |
|---|---|
| 训练集切分与导出 | 在 **版本 → 训练集** 里，对一个不可变版本按种子预览并保存训练/验证/测试切分。分层会照顾到每个标签，多标签样本也算；同一元数据分组、互为重复的样本不会被拆到不同集合。泄漏检查逐对列出完全相同、图片近重复（dHash）、文本近重复（SimHash）和同组样本。通过要签批的 `export_dataset` 导出 COCO、YOLO、ImageFolder、Hugging Face imagefolder 或文本 JSONL；导出包绑定版本、切分和标注员，重复导出逐字节一致。同样的事也能用 `datakeel training …`、HTTP 和只读工具 `training_distribution`、`training_leakage` 做。见[训练集说明](TRAINING.zh.md)。 |
| 大模型训练数据治理 | 打开数据集的 **文本数据治理** 页，检查 SFT、指令和偏好 JSONL：格式、长度、语言、质量规则、完全重复和近重复、同一提问不同回答、个人信息和凭证，以及和你自己登记的评测集有没有重叠。分析只出结果、不改数据；要生成清洗后的版本，必须有人签批 `clean_training_data` 计划，新版本带血缘。`datakeel training-quality` 和只读工具 `get_training_quality` 能直接回答「这个数据集有什么问题」。装上可选的 Rust 加速后，开发机上 10 万条不到一分钟查完。见[大模型数据说明](LLM_DATA.zh.md)。 |
| 生产项目与角色 | 项目钉住一个数据集版本和一个已发布的标签集，把任务分成任务包，导入离线的 COCO/YOLO 预测，用只追加的修订记录标注，小组项目里可以审核、打回、再提交，最后把通过的结果定稿成一个普通的数据集新版本。用户、团队和五个可改的角色模板决定谁能做什么，权限范围由服务端算。`datakeel production demo` 会建一个小的个人项目。见[生产流程](PRODUCTION.zh.md)和[身份与 HTTP 访问](IDENTITY_ACCESS.zh.md)。 |
| 标注工作台 | 从侧栏打开 **标注工作台**（`#/labeling`），用键盘或鼠标标框、多边形、分类和文本片段。标注员看到「我的任务」，质检员看到「审核队列」，项目经理看到「项目驾驶舱」，个人项目是「我的数据」。改动先存本地草稿，停半秒自动保存；断网、刷新、两人同时改都不会悄悄丢数据。能撤销重做，提前加载后两条任务，大图先出缩略图再换原图，切换很快。定稿后的标注可以按 `annotations_jsonl` 无损导出再导回。见[工作台说明](ANNOTATION_WORKBENCH.zh.md)。 |
| 两批小修 | 质量规则扫整张表并写明覆盖了多少行；标注一致性按人计票；数据标准建议把金额、周期、状态、日期/时间分开；说明书核对数字时会看数的是什么；音频算子分块解码（一段生成的 30 分钟录音，峰值内存从 5.78 GB 降到 142 MB）；上传和发布页面的提示更清楚；隐私识别认得中文凭证标签，也不会再吞掉紧跟的中文。 |

**登记第一个用户后，角色权限开始生效。** 一个用户都没登记时，行为和以前完全一样。登记之后，HTTP 写操作以请求头 `X-Datakeel-Actor` 指定的人身份执行；每个动作和旧的写接口都要检查权限范围，范围由服务端按全局和项目的角色绑定算出来；没登记、已停用或已归档的人只能读。训练切分、导入标注、文本清洗这几个写入口分别归到 `export_dataset`、`save_metadata` 和 `clean_training_data`。这个请求头只是在本机可信环境里标明是谁操作，不是登录认证；部署时的认证仍要自己把关。

**MCP 工具从 57 个变成 92 个**：33 个只读函数，59 个只准备计划的动作。仍然没有签批和执行工具。把工具列表写死的 MCP 客户端需要刷新一下。

**其他行为变化。** `text.pii_redact` 用默认替换值时，输出改成分类型的占位符，比如 `[EMAIL]`、`[PHONE]`，不再是 `[REDACTED]`；记忆写入仍用 `[REDACTED]`。手机号识别要求前后都不是数字：12 位、14 位的裸订单号不再当成电话，带括号区号的固话现在能识别。COCO、YOLO 和 Hugging Face imagefolder 导出遇到 EXIF 里带旋转或镜像的图片会拒绝。质量规则的 `max_rows` 现在只限制每次读多少行，不再限制总共查多少行。没有改名任何 CLI 命令、HTTP 路径、MCP 工具、算子或数据表；OpenAPI 路径从 144 个增加到 164 个，一个没删。变异锚 376 个，golden 用例 52 条，算子 42 个。

已知边界：

- 训练集导出：文本近重复按字符三元组算，80 个字符以内、只差几个数字的文本不报近重复，中文一整段只要在这个长度内也一样。图片任意一边裁掉超过 10%，不在近重复检测的保证范围内。分层是有界搜索，有些小比例本来就凑不出来，这时报告给出实际分布。
- 隐私识别靠规则。少数情况会多打码：英文通用标签，比如 `The secret: practice every day.`；长得像括号区号的编号，比如 `编号（010）2024-0315号`、`(300) 200 3000`。识别不了的写法有：带前缀的键名 `DB_PASSWORD=`、`mysql_pwd=`，`password is …`，`私钥：`，全角 `＝`，以及不到 8 位的密码。两个固话之间只隔一个空格时，两个都识别不出来。紧跟在裸凭证后面的 `～ · ｜ 〉 』 〕 〗` 会被一起打掉。用户名和密码打码后，中文主机名仍然可见。近重复查找对每条记录的候选数有上限，语料很密时可能漏掉。安全词表粗筛这一版没有。「10 万条一分钟」要装 Rust 加速；纯 Python 结果一样，只是更慢。
- 生产项目：没有用户时写下的任务属于 `local`；之后登记了别的用户再升档，这些任务会一直指派给没登记的 `local`，要把 `local` 登记成用户并给标注员角色才能接着做。普通图片导入不记宽高，所以导入 YOLO 预测要自己带 `image_width`、`image_height`，多张图的 COCO 结果数组要每张图都对得上 ID 和宽高。`reopen_task` 对待标和进行中的任务也会让轮次加 1。项目经理只有全局绑定时才能导出训练集，而且 `datasets:export` 同时也能发布数据表。模板是所有用它的项目共用的，改模板会影响全部项目。团队档的心跳、按技能派活、标注和审核分人、任务包验收留到以后。
- 标注工作台：画布高度固定 480 px；框不按标签上色，画布上也不显示标签名；属性要手写 JSON；方向键每按一次只移动 1 个原图像素；任务列表显示的是样本 ID，不是文件名；定稿计划直接显示原始参数；打开着的任务被别人打回后不会自己刷新。预标注准确率只算完全一致，对框来说偏严。画多边形时点在已有标注上不会加点；按住 Option+P 往回翻、跨页时可能少走一条。大图是先缩略图后原图，不是切片加载；没有 service worker，完全断网时刷新能不能打开要看浏览器缓存。
- 说明书：数字核对仍是规则做的；在一组专门挑刺的留出句子上，48 句正确的里还会删掉 6 句，77 句没依据的里还会放过 8 句。

本版的集成改动：

- PostgreSQL 启动时，训练、大模型数据和生产相关的触发器只在缺失或指错函数时才重建，重启不会再排在未提交的写入后面卡住；指错函数的旧触发器会自动改回来。
- 训练切分、导入标注、文本治理这几个写接口接入角色权限，文本治理的清洗接口会记下真实的 HTTP 操作人，项目经理模板加上 `datasets:export`。
- 导入 COCO 预测时，优先用训练导出写进去的 `datakeel_sample_id` 对样本，训练集导出后可以原样导回来。
- macOS 上，焦点在文本框里时 Option+N / Option+P 留给输入，不再翻任务。
- Agent 和其他生产只读函数一样，通过 `tool_search` 按需找到 `production_prelabel_accuracy`，不再每次请求都带上它的参数说明。
- 大模型训练数据的代码模块叫 `llm_data`，和训练集切分分开；对外的名字都没变。
