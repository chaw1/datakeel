# 一句话做事（试用）

[English](ONE_SENTENCE.md)

> **这是试用功能。** 在没见过的说法上，大约八成能直接给出正确的计划；剩下的可能多问一句、说做不到，或者给出不对的计划。所有会改数据的动作都要你确认后才执行，计划不对时取消即可，什么都不会改；只读的问题直接回答，不改任何东西。规划默认用 DeepSeek Flash（`deepseek-flash`），思考开着（DeepSeek 的默认）。界面上的入口和每张结果卡片都标着「试用」。

在智能体对话里直接说要做什么，例如「给这批路口图建红绿灯框标注，两人交叉、抽 10%」。Datakeel 把这句话拆成一串已有的受控动作，列出每一步做什么、改多少、花多少、要不要签字；在你确认之前什么都不执行。像「这周谁的返工率最高」这样的问题，直接用读函数回答。

## 怎么理解一句话

1. **先走规则，但要用上全部信息。** 几个固定说法（建标注项目、把某人没动的任务收回分给别人、起草标签集）和简单的查询问题，不用模型就能识别。配了模型时，只有固定说法用上了这句话里的每个对象和数字（「5000 张」、数据集名字）才走规则，否则交给模型规划。两条路走同一套检查。
2. **再调一次模型。** 规则认不出时，用会话所配的模型调用一次，有上限。提示词里有登记表（每个动作和读函数的参数签名：必填项有标记、可选值直接列出，以及中英文说法）、最可能的 4 个动作的完整参数表、能看到的对象（人员并标出停用的账号、项目、数据集、版本、标签集、技能及其标注类型和领域）、说话人的角色和页面上下文。请求要求温度 0、只回一个 JSON 对象，否则丢弃。
3. **严格检查。** 每一步必须是登记过的动作、参数合法。名字到目录里去对（名字、英文名、ID、别名都算，当前页面上的对象优先）：对上一个就用，对上多个让人选，一个都没有就问。「我」「me」指说话的人。写操作用到的项目、任务包、数据集、标签集，必须来自当前页面、上一轮、前面的步骤或者这句话本身（模型要引用它对应的原话，所以「那个自动生成的项目」这类翻译过的说法，只有原话真在句子里才算）；模型从目录里抄来的值会变回提问。只有读操作才会在只有一个项目时默认用它。
4. **什么都不悄悄丢。** 动作没有的参数，先让模型修一次；还不认识就问人。每句话最后都是计划、回答、追问、拒绝（只用于缺权限）、如实说明模型调用失败及原因（超时、HTTP 状态、网络，或回答两次都读不了），或者明说「这件事做不到」并列出平台能做什么。「做不到」只在登记表里没有任何相关动作时用；模型认为有相关动作时，带上候选问人想做哪一个。内部错误只说一句人话，不露原始报错。不会掉进自由对话。

参数来源：这句话本身、页面上下文、上一轮涉及的对象。标注页上的「一句话做事」按钮打开对话时带上项目、数据集、版本、标签集、任务包和当前打开的任务；任何页面都可以链接到 `#/agent?project=…&task=…&selected_kind=production_task&selected=a,b`，HTTP 接口接受同样的 `context`。序数按列表显示的顺序算（「前两个任务」「第 8 个任务」「#8」「第 2 个任务包」），位置不存在就问。说的是一部分（「重复的图」「选中的几行」）时，先解析成具体对象再出卡片；计划范围比这句话大就改成追问。缺必填参数用自然语言问，最多给 5 个一键候选，不向人要 ID；选填参数用默认值，卡片上标明。先查权限：没有权限的请求在问任何问题之前就拒绝，并说出缺哪个权限（例如 `production:manage`），和手动做同一个动作时一样。

计划卡片按人能看懂的方式列出每一步的参数：名字而不是 ID，数量加前几个名字，默认值有标记。修改已有标签集从当前版本开始：「加一个行人标签」会保留原有的全部标签，卡片列出新增、删除、改名，以及受影响的标注数（和 `label_set_diff` 同一个口径）。标签可以用 ID、名字或译名指代；删除和改名会带上新版本需要的迁移说明（改名保留标签 ID，删除的标签已有标注转人工处理），迁移按最终标签列表推出，不照搬模型写的；说了标签集里没有的标签会追问。任务没有名字，卡片按任务列表里的位置显示（「第 1 个、第 2 个」）；文件显示文件名。新建技能、角色、团队或人员时 ID 取自名字；执行时才会要求的值（新技能的标注类型和领域）在出卡片之前就追问；「给小李加一个车辆框技能」是在小李已有技能上追加。起草卡片上的样本显示文件名；直接回答的问题只用名字和数字概括，不露 ID（完整数据仍在回答的 `data` 里）。模型回答里错了一个括号会先修复再读（只改一个闭括号，修完必须能完整解析）；写进参数里的原话对照表按步骤自己的读；仍然读不了就再问模型一次，第二次还不行就如实说明模型调用失败。

Web 智能体对话每条消息都会进入规划（它总是带页面上下文）。Web 新建会话用配置好的模型（`DATAKEEL_OPENAI_API_KEY` 或 `DATAKEEL_ANTHROPIC_API_KEY`）。选 auto 时只路由到已配置地址对应的模型；只配了 DeepSeek 时三档都是 deepseek-flash；只有没配密钥时才用离线演示模型，没有可用模型时页面会写明是配置问题。HTTP 发消息接口只有带 `context` 时才进入规划，老的客户端行为不变。

## 范围和固定校验

**先查对象，再出计划。** 模型按人说的话描述要动哪些任务（谁手上的、没人领的、没动的、返工超过 N 轮的、哪个包的、第几个/#N、前 N 个），Datakeel 先从项目里把这组任务读出来再出卡片，卡片列的就是确认后会改的任务。对一组任务做写操作时，默认不动别人手上的和已经保存过人工标注的任务，除非话里明说（「已经标了的也收」、点名是谁手上的、说了返工轮数）；收回任务只默认排除已有标注的。卡片写明排除了几条、为什么。只说「任务」不说范围时会先问是不是全部，不会扩大到整个项目；改整个数据集的文件，话里必须有「全部/所有」。

**每个计划都过一遍固定校验，不靠模型。** 改了等于没改的计划（标签已经有了、时限本来就是这个值、账号本来就是启用的、任务本来就在这个人手上）直接回答「已经是这样了」，不出卡片。动作要和说话人的动词、角色对得上（审核员说「打回」是审核决定，不是重新打开；标注员说「放回去」是放弃任务）；调云端模型或花钱的步骤，话里必须有起草、预标注、用模型之类的意思；点名已有标签集而没说「新建」时改原来的，不另建一个同名的；整表写技能或团队时不能丢掉没提到的原有项。发现问题先让模型修一回合，修不好就问人。停用的账号能认出来，不派活：追问里说明账号已停用，并给出在用的人选。审核决定没写修订版本时用任务最新的修订；后面的步骤可以取前一步产出列表里的某一个（`{"$ref": "s1.package_ids", "$nth": 1}` 是切包产出的第一个包）。

## 动作链、确认和续跑

计划存成一条动作链，每一步都是普通的受控动作；`{"$ref": "s1.label_set_id"}` 表示用前面某一步回执里的值，一步可以对多个对象分别执行。

- **确认**：人点「确认执行」（或命令行 `datakeel intents run <chain>`；HTTP `POST /api/intents/chains/{id}/run`）。每一步按顺序准备和执行，走的是和手动操作相同的服务，所以回执、审计、血缘完全一样，署名是本人。
- **依赖前步的后步**：领取、派单、释放、收回、提交、审核、升级等动作如果依赖同一计划前一步留下的任务持有、任务状态、档位或派单策略，第一步仍保留并可执行，依赖的后步不生成执行卡，结果和链备注明确写「上一步完成后再规划」。这不是执行失败，原来想做的事项会保留在说明里；前步完成后，用新状态再说一次下一步即可继续。
- **签字**：不可逆、外发或受治理的步骤进审批队列等签字。可以直接在动作链卡片里签，也可以去审批页签，签完动作链继续。签批人是发起请求的本人；浏览器传来的占位名 `local` 记为本人，写别人的名字会被拒绝。
- **失败**：停在失败的那一步并写明原因，已完成的步骤保留。点「续跑」（或同样的命令行/HTTP 调用）会跳过已经执行过的步骤和对象，绝不重做。签批被退回也算这一步失败；续跑会重新生成一张签批单等人签。
- 只有提出请求的人能查看和执行这条动作链。MCP 和智能体永远不能确认或执行写操作：MCP 没有动作链工具，智能体只负责提议。

命令行 `datakeel intents plan "<一句话>" [--dataset --version --project --package --actor]` 可以直接规划，`datakeel intents show <chain>` 查看。

## 说法登记（每个动作都必须有）

一句话入口只读动作登记表。每个动作和读函数都必须登记中文、英文说法，以及至少两条例句（中文、英文各一条）。缺任何一项，门禁测试 `tests/intents/test_language_gate.py` 就会失败。新动作在 `datakeel/actions/action_language.py`（`ACTION_LANGUAGE`）或 `datakeel/actions/production_language.py`（`PRODUCTION_LANGUAGE`）里加一个四元组：`(中文说法, 英文说法, 中文例句, 英文例句)`。读函数在 `datakeel/ontology/function_language.py` 里登记。

## 起草标签集和标注指南

`draft_label_set` 是受控动作（「按这批图起草一份车辆标签和标注指南」）。它需要签字，签字前什么都不写。它读取：

- **数据标准**：列的是物体类别的代码表都变成标签子树（字段是父标签，「信号灯类别」→「信号灯」下面每种一个子标签）；表示状态或属性的代码表（颜色、遮挡、是/否）变成属性，挂到它名字对应的子树上。每个判断的依据写进起草稿的来源说明；
- **已有标注**：数据集已有标注批次里的类别，以及以前的标签集；已标注的样本用作正例和反例，没选样本文件时也一样；
- **抽样文件**：数据集版本里最多 50 个文件。

结果是一个新的**未发布**标签集版本：中英文名、属性、总说明和每个标签的指南，带正例和反例。每个标签都有规则；模型漏掉的名字、属性、例子从来源补齐。例子引用的都是真实样本 ID，模型编造的 ID 会被丢掉并计数。这个版本记录了来源（数据标准、标签集、数据集、样本、模型、token、费用、计划编号）。在动作链卡片里可以改名字和指南，点「保存修改」（生成一张 `create_label_set` 更新计划），再点「发布…」走普通的 `publish_label_set` 签批单。

模式：`offline`（默认，确定性，不花钱）；`cloud-text`（`deepseek-flash`，密钥放 `DATAKEEL_DRAFT_TEXT_API_KEY`）；`cloud-vision`（百炼上的 `qwen3.5-flash`，会带缩略图，密钥放 `DATAKEEL_DRAFT_VISION_API_KEY`）。云端起草在签批单上显示预估费用；签批的 `max_cost_usd` 低于预估时拒绝执行。规划和执行按同一口径计数来源（每个类别只算一次），按预估签批的起草不会因为计数不同被拒。`cloud-text` 生成结构化结果时关掉 DeepSeek 的思考。已经计费但答案不能用的调用会让这次执行失败，并把 token 和费用写进执行记录的错误里。不指定 `profile` 时，配了密钥就用 `cloud-vision`（有样本）或 `cloud-text`，否则用 `offline`。模型和地址可以用 `DATAKEEL_DRAFT_TEXT_MODEL`/`_BASE_URL`、`DATAKEEL_DRAFT_VISION_MODEL`/`_BASE_URL` 修改。

起草的输出上限按标签数估算（4000 起、最多 8192），计划预算包含一次修复回合。模型字段名写错（如 key 写成 id、name_cn）会直接映射；读不了的条目或被截断的回答会带着问题清单回模型修一回合，修不好也保留能用的部分。标准、抽样、已有标注及其组合都会产出中英文名、属性和正反例：已有标注里填过的属性成为属性定义；没有可引用样本时，规则里写文字正反例；总说明按实际计数写明正反例来自哪里。每次计费的起草调用（包括失败的）都记成调用轨迹，花费汇总里能看到。

## 限制

- `rework_rate` 统计项目的全部审核记录，不按「这周」筛选，回答里会说明。
- 规划用的模型就是会话的模型，输出上限留到 4000 token，推理模型想完之后还能给出 JSON；离线演示模型只用固定说法。
