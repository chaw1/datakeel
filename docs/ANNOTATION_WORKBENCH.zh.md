# 标注工作台

从侧栏打开**标注工作台**（`#/labeling`），原有工作概览继续保留。选择生产项目和任务包：个人档只有**我的数据**，小组档和团队档按服务器有效权限显示**我的任务**、**审核队列**、**项目驾驶舱**。通过现有 production CLI 创建项目、已发布标签集和任务包；`datakeel production demo` 可生成带离线预测的个人框标注项目。

顶部模块栏展示项目、任务包和真实生产进度；操作栏写明当前文件名，提供保存、撤销、重做、提交和导航。打开任务后页面去掉大标题和页脚，作业区占满两条栏下方的窗口高度，随窗口缩放；图片工具和缩放按钮在左侧窄栏。右侧抽屉（属性、不可变修订历史、审核意见、指南）可以用**收起侧栏**收起，画布随之变宽。我的任务、审核队列和驾驶舱都显示文件名；鼠标悬停显示它在导入目录里的相对路径，搜索框同时匹配文件名和目录名，不同目录下的同名文件能分开。导入目录时记录每个文件相对导入根目录的路径（目录里的隐藏文件和符号链接跳过）；导入机器上的绝对路径不会出现在任何 API 响应和界面上。单独导入的文件、以及之前导入的老数据集，照旧显示文件名。

框和多边形用标签集给该标签配的颜色；没配色的标签按标签顺序取一套固定的 8 色色板（`--label-1`…`--label-8`，浅色、深色都过 `check:contrast`）。每个形状旁边有标签名小标签，缩放时保持屏幕上大小不变。小标签在屏幕上不比它的形状宽（56–160 像素），名字更长就以省略号结尾，鼠标悬停显示全名。小标签不接鼠标：在它上面按下，画框、加多边形的点、选中形状，都和按在它下面的画布或形状上一样。形状只要还有一部分在屏幕上，小标签就被拉回可见画布内，放大看大框的一角也能看到它叫什么。

## 模板和键盘操作

模板复用现有带版本的 `ProductionTemplate`，标签来自项目关联的已发布标签集版本。没有模板时默认使用框。`annotation_type` 定义主要组件，`component_config` 可配置：

```json
{
  "components": ["box", "classification"],
  "label_mode": "multi",
  "shortcuts": {"cat": "1", "dog": "2"},
  "guidelines": "只标注可见物体。"
}
```

模板还可以定义带类型的属性字段（`attributes`）：布尔 `boolean`、单选 `enum`、多选 `multi_enum`、数字 `number`（可带范围）、短文本 `text`。每个字段有中英文名、是否必填、默认值，`target` 为 `object`（每个框、多边形、文本片段）或 `record`（整条数据）。工作台把它们渲染成原生表单控件；必填没填时既不自动保存（状态显示「没保存 · 先把必填属性填上」）也不能提交，并指出是第几个形状的哪个字段。服务端按同样规则校验，返回 422 并写明字段名，绕过界面的请求同样被拒。没定义字段的老模板，任务照常打开和保存；标注员和质检员不再看到原始 JSON 属性，项目经理可以在**高级：原始属性**里编辑。字段结构及与 CVAT、Label Studio、Labelbox 的对比见 [PRODUCTION.zh.md](PRODUCTION.zh.md)。

首批组件是框、多边形、分类和文本片段。标签名称是用户内容，标注保存稳定标签 ID。项目经理通过模板配置界面调用 `create_label_set` 保存新版本。保留 P29 已有共享模板语义：关联同一模板 ID 的项目使用该模板当前目录版本；抽屉展示模板名称、修订号和标签集版本。

所有控件可通过 Tab 到达。编辑器内按 `?` 打开快捷键表；`Ctrl/⌘+S` 保存，`Ctrl/⌘+Enter` 提交，`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z` 或 `Ctrl/⌘+Y` 重做，`Alt+N`/`Alt+P` 保存后切换任务；页面或任务加载期间按下的翻页键会排队，加载完按顺序执行，快速连按跨页也停在正确位置。文本输入框保留原生文本撤销。

- 框：`B` 添加，方向键一次移动 1 个原图像素，Shift+方向键一次 10 个；`R` 把方向键切到调右下边、再调左上边、再回到移动（左侧栏写明当前状态）；`Ctrl/⌘+D` 复制，Delete 删除。拖画、变换手柄和坐标字段都以原图像素坐标为准。
- 多边形：`P` 开始，方向键移动光标 1 个原图像素（Shift 10 个），Space 或点击加点，点在已有标注上也加点；Enter 闭合，Escape 取消。不在绘制时点已有形状是选中它。方向键移动整个多边形，`R` 切到移动选中的点。剩余点数有效时可用 Backspace 删点。
- 分类：单选或多选控件支持 Tab、Space 和方向键，也支持标签快捷键；`label_mode` 控制单选/多选。
- 文本：鼠标或 Shift+方向键选字后按 Enter，也可填写起止位置；支持嵌套。坐标按原文 Unicode 码点计数，与 Python 一致，保留 emoji 和 CRLF 原文位置。

## 自动保存和审核

改动立即保留为本机草稿，500 毫秒防抖后通过 `save_revision` 保存。请求串行化；保存途中产生的新改动会继续补存。草稿按用户、项目、任务隔离；同一标签页的工作区快照帮助刷新后恢复当前任务。恢复草稿须先核验服务器身份才可同步。完全断网刷新时能否加载网页本身取决于浏览器和静态托管缓存，本期未安装 service worker。

预取后两条任务、修订及已解码图片。切换前先补存，离线或冲突会保留当前草稿。撤销历史不设固定步数上限，实际受设备内存/存储限制；未保存草稿可刷新恢复，已完成的撤销时间线保留在当前会话。

409 会显示明确提示：选择**重新加载服务器修订**才放弃本机改动；选择**用我的改动覆盖**会重新读取当前修订，再做比较并交换保存。如果同时发生另一笔写入，仍会再次显示冲突。设备存储失败有警告，恢复联网后自动补存。

## 打开中的任务自己刷新

打开的任务每 5 秒读一次 `GET /api/production/tasks/{id}/status`；标签页在后台时放慢到 30 秒一次，回到前台立即补读一次；续租不因后台而停。任务被打回返工、在别处改了状态、或别人保存了新修订，页面在这个间隔内提示，并给出**重新加载服务器修订**或**回到列表**；本机没保存的草稿始终保留。如果提交后读回的任务已经是下一轮的待标注，同样按「被打回」提示，并显示质检意见。团队档打开任务时自动通过 `heartbeat` 续租，之后每 2 分钟一次；租约短于 6 分钟时改为每隔租约时长的三分之一续一次（时长以上次续租时服务端给的为准），剩余时间显示在保存状态下面、工具栏左边，不占画布高度；续租失败会显示出来并带**立即续租**，同时自动重试。租约到期、被收回、或保存时被告知租约已过期或任务已归别人，编辑区锁住，「这条任务已被收回」的提示换掉工具栏；保存状态显示「未保存 · 草稿留在本机」而不是保存失败，`Ctrl/⌘+S` 和 `Ctrl/⌘+Enter` 不再发请求，草稿可以导出成 JSON。此时点**回到列表**会立刻离开，不再等一次注定失败的保存，并重新读取列表，显示新的持有人和状态。并发导致的 409（「Action target state changed after preparation」）显示为「任务刚被别人改过」并给出**重新操作**，不显示原始英文报错。

| 方案 | 这里需要什么 | 延迟 | 代价和故障点 | 结论 |
|---|---|---|---|---|
| 轮询一个很小的状态读接口 | 每个打开的任务一次走索引的读；任何代理、SQLite 都能用 | 不超过轮询间隔（5 秒，在 10 秒预算内） | 每个标签页每 5 秒一个请求；没有连接要维持 | **选用** |
| 服务端推送 SSE（[HTML 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)、[MDN EventSource](https://developer.mozilla.org/en-US/docs/Web/API/EventSource)） | 每个标签页一条长连接，外加所有 API 进程都能看到的变更源（数据库通知或消息中间件） | 几乎即时 | HTTP/1.1 下浏览器对同一主机大约只给 6 条连接，所有标签页共用（[EventSource 的坑](https://textslashplain.com/2019/12/04/the-pitfalls-of-eventsource-over-http-1-1/)）；会缓冲的代理会拖延事件；断线重连和漏掉事件的补发都要自己做 | 暂不用 |
| WebSocket | 同样的变更源，加双向协议和升级时的鉴权 | 几乎即时 | 部件最多；单向通知用不上双向 | 暂不用 |

轮询复用现有读路径和权限校验，不加依赖。以后真要推送，在数据库变更源上加 SSE 是最小的一步；页面逻辑只要换一个来源，拿到的还是同一个状态对象。

个人档提交即通过；小组审核针对确切当前修订通过或填写意见打回，返工保留原标注员。审核队列按返工轮次、模型置信度、预标注差异、稳定任务 ID 排序。差异是精确标签/形状/属性集合的 1−多重集 Jaccard，一致性信号不等于模型准确率。驾驶舱直接展示 P29 进度、人员工作量、置信度分布、标注一致性、以审核通过结果为参考的预标注完全一致率和多轮返工任务，不另存一套数字。定稿先用大白话显示冻结的计划：要定稿几条已通过的任务、写进哪个数据集生成新版本、还有几条没通过会挡住定稿；计划摘要和原始参数收在**详情**里。再由人单独点击**签批并定稿项目**。

团队档的驾驶舱另外显示：每个任务包的验收状态和抽检情况（读 `package_acceptance`：未验收时显示抽检规则，验收或拒收后显示上次抽了多少条）；**整包验收**——项目经理逐条标出抽中的任务有没有问题，准备 `accept_package` 计划，计划写明结果，再签批；**按技能派单**——先预览每人分到几条、哪些没派出去及原因（`dispatch-preview`），再准备并签批 `strategy: "skill"` 的 `assign_tasks` 计划（数据刷新后勾选重置为当前还待派的任务；项目没设技能要求时直接说明，不给一个注定失败的预览）；**派给指定的人**——列出登记过、在本项目有标注权限的人和他们手上的任务数（`GET /api/production/projects/{id}/assignees`，只有能派单的人能读），对勾选的、没人持有的任务准备并签批指名的 `assign_tasks` 计划；**谁手上有什么**（`lease_status`）——项目经理通过签批的 `revoke_assignment` 计划把任务从持有人手里收回。团队档的审核队列不列出审核人自己标过的任务；打开自己任何一轮标过的任务时，也不显示通过和打回按钮。即使绕过界面，服务端同样拒绝。零用户阶段派给 `local` 的任务，升到团队档后会出现在这里；项目经理收回后直接派给指定的人，不需要先把 `local` 登记成用户。MCP 和 Agent 仍然只能准备这些计划，签批和执行只能人在界面上点。MCP 的身份固定是 `local`，登记用户之后它和没带登记身份的 HTTP 请求一样被拒。

界面隐藏无有效范围的动作，写入仍走已有受控动作和服务端角色、归属校验。样本读取复用项目与源文件授权。零用户实例保留本机个人档行为。

## 无损往返

`AnnotationRecord` 增加可选多边形以及记录、形状和文本片段属性，保留旧字段与接口。定稿后通过受控 `export_dataset`，选择 `annotations_jsonl` 格式；归档中的 `annotations.jsonl` 保存完整核心记录。用已有版本训练集 `import-annotations` 接口传入 `format: "annotations_jsonl"`、`annotations_jsonl` 内容和新的 `idempotency_key` 即可导回。COCO/YOLO 行为不变，检测格式无法表达全部四种组件及属性。

## 画布选型

直接运行时依赖只新增固定版本 Konva **10.9.0** 和 react-konva **19.3.2**，传递闭包及实际打包模块纳入现有许可审计。Konva 是已定选择；以下适配判断是根据上游文档做出的工程推断。

许可来源：[Konva](https://github.com/konvajs/konva/blob/master/LICENSE)、[react-konva](https://github.com/konvajs/react-konva/blob/master/LICENSE)、[Fabric.js](https://github.com/fabricjs/fabric.js/blob/master/LICENSE)、[PixiJS](https://github.com/pixijs/pixijs/blob/dev/LICENSE)。

| 方案 | 上游能力及来源 | 对本工作台的适配判断 |
|---|---|---|
| [Konva](https://konvajs.org/docs/overview.html)、[react-konva](https://github.com/konvajs/react-konva) | Canvas 场景图、命中检测、分层、变换和 React 绑定；MIT | 已选。声明式形状编辑能对接 React 状态和撤销历史，原生 DOM 控件提供键盘可访问性。 |
| [Fabric.js](https://www.fabricjs.com/docs/) | 交互对象画布、控制点、自定义属性及序列化；MIT | 可以承担对象编辑，但独立画布对象状态需要额外维护与 React 的同步。 |
| [PixiJS](https://pixijs.com/8.x/guides/concepts/render-loop) | GPU 场景渲染和连续渲染循环；MIT | 适合密集动态场景，标注控制点、表单和可访问行为需自行补充。 |
| [Canvas2D](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API) / [SVG](https://www.w3.org/TR/SVG2/) | 浏览器原生栅格绘制 / 向量 DOM | 不新增库，但命中检测、选择、变换及状态同步需要自己维护；SVG 适用于较小的 DOM 图形。 |

Konva 画布按视口尺寸分配；大图提供最长边 1024 像素缩略图，再换成高清原图。缩放平移只变换组，不分配 8000×6000 的画布。这里采用渐进加载，没有实现分块服务；性能须在目标浏览器和硬件实测。

## 可重复验证

生成纯本机样本（含 2000×1500、3840×2160、8000×6000 图片）：

```sh
DATAKEEL_HOME=/tmp/workbench-home uv run python scripts/workbench_fixture.py \
  --output /tmp/workbench-manifest.json --source-dir /tmp/workbench-source
DATAKEEL_HOME=/tmp/workbench-home uv run python scripts/workbench_fixture.py --serve
cd web
npm run smoke:workbench -- http://127.0.0.1:8840 /tmp/workbench-evidence /tmp/workbench-manifest.json
```

脚本使用真实 API 验证 W1–W5：纯键盘标注并提交、离线恢复和显式冲突选择、四种组件各 200 步撤销重做、大图平移五秒，并记录性能数据及浅深色截图。每次全量运行使用新生成的样本。PostgreSQL 使用 `--test-database --schema p30_workbench`，由宿主提供已明确授权的隔离测试库，不能使用归属不明或共享库。Web/API 只使用 8840。

Vitest 覆盖渲染和状态，严格类型、lint、API、token、对比度、源码哈希、构建和许可检查照常执行。沙箱阻止浏览器启动属于未测量，不能记成性能通过。本任务完整两栈门禁和全量变异由集成 CI 执行。
