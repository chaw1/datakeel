# Independent intersection and acceptance protocol v1

The implementer processes only this checkout's declared development artifacts. No command,
argument, directory walk, search, log retrieval, connector or helper accepts a held-out source.
E1 has no holdout comparison CLI. A different session under independent custody must perform
the actual comparison. This document conveys a protocol; it does not claim an audit occurred.

Development partitioning joins connected components across stable source identity, original
content SHA-256, variant content SHA-256, original semantic group, near-duplicate cluster and
transformation family. Prefix the identity domains to avoid accidental cross-domain matches.
For each component, hash UTF-8 `seed + newline + sorted(non-variant-content identity keys)`;
seed=`we-e1-development-v1`; even integer hash goes to dev_tune, odd to dev_validation.
Sort final assets by asset ID. Whole components stay together. The development ratio is an
expected 1:1 hash partition, not an exact sample quota. Adding a variant with existing root
identities preserves the split. New links change components and require a new freeze.
This splitter covers only tiny synthetic and real development artifacts; no E5 capacity claim is made.

Independent final campaign data is outside both development partitions. Never send its
rows, content, identities, family names, sample-level failures, filenames or paths to the
implementer. Only the aggregate summary schema is shared. Do not obtain held-out information
from earlier task logs or another agent. A suspected leak invalidates custody: independent
custodian regenerates the affected held-out material before implementation can proceed.

Independent reviewer procedure, using only development material until its own authorized
custody step:

1. Verify branch/baseline and inspect the full allowed E1 diff, including untracked files.
   Confirm no product/dependency changes and no stage/commit/publication. Run `WE-COMMANDS.md`
   with existing tools; require matching generated bytes, schemas, negative controls and hashes.
   Read actual logs/exit codes; a missing dependency or public-gate exit 2 is not a pass.
2. Read `artifacts/we/development-public-evidence.json` (also copied separately to the task
   handoff). Confirm `kind=public_development_only`, actual nonempty rows and independently
   reviewed upstream provenance. The current export contains eight text originals and one locally CC0-eligible image
   (page `152924098`, revision `1199020912`); independent per-file review remains pending.
   Bind `public-manifest.json` and `license-ledger.json`; synthetic fixtures must never
   substitute for public rows. Rejected page `6372844` and descendants are history only,
   excluded from the new baseline. The previous aggregate is stale and cannot authorize
   this changed development set; rerun comparison for all 19 current assets.
3. Bind the development-public-evidence SHA-256, development manifest/generator inventory,
   grid and spec/amendment bundle digest to the independent audit. Independently recompute
   stable source identities: Wiki dataset/config revision + split + row index; Commons pageid
   + revid, retaining pageid alone as an additional cross-revision source-family identity.
   Recompute original bytes' SHA-256; do not trust filenames or implementer-supplied labels.
4. Only the independent custodian, in its separately authorized environment, compares actual
   development and held-out evidence in five dimensions: stable source (including cross-revision
   source families), original content hash, transformation family rooted in the original,
   semantic group, and near-duplicate cluster. Compute exact set intersections per dimension.
   Use source-qualified canonical identities; where local labels differ, independently derive
   shared component identities from original-source/content/near-duplicate lineage. Inspect
   cross-source copies and transformed descendants; disjoint random group IDs alone are not proof.
   Any nonempty intersection fails. Empty datasets or unknown grouping/provenance fail.
5. Audit all session commands and file scopes, including command journal and any initial reads
   in the session transcript, for direct/indirect access, leakage and tuning. An audit cannot
   be certified solely from an implementer's `network_calls=0` or `holdout_access` declaration.
   After the final development freeze, the custodian privately generates/keeps held-out
   material with directory/file modes 0700/0600; retain creation, transcript/command review,
   zero implementer reads after creation and public/internal leak-scan evidence. This is
   executable access evidence, not a claim of historical OS audit records that do not exist.
   If the new image or any intersection fails, reject or regenerate the affected collection.
6. Return only a strict `IndependentSummary` aggregate, bound to the actual development hashes
   and spec bundle. `checked_dimensions` and corresponding `overlap_counts` order is exactly
   stable_source, original_content, transformation_family, semantic_group,
   near_duplicate_cluster. Require positive development_public_rows/holdout_rows, zero overlaps,
   complete command audit and no implementer holdout access for `result=pass`. Custody retains
   raw comparison evidence; it is not copied into this checkout. The schema is a consistency
   check, not proof of independence/authenticity. No valid summary for the new freeze exists in this delivery.

After E1 is independently accepted, E2 may implement fake-only product work. Tune only with
development partitions after implementation, then freeze selected parameters/configuration
and predeclare a single final campaign before any held-out result is released. Cold/hot/
incremental/fault runs belong to that one campaign; they cannot guide retuning. A changed
dataset/generator/configuration requires independent re-audit. Real text/image egress still
requires the spec's separate approval/evidence/budget gates; E1 acceptance does not authorize it.
