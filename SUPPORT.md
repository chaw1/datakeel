## Questions, bugs & feature requests / 提问、缺陷与建议

Before opening a new issue, please search [existing issues](https://github.com/chaw1/datakeel/issues) to see whether the topic has already been discussed or fixed in [CHANGELOG.md](CHANGELOG.md).

提交新 issue 前，请先检索[已有问题](https://github.com/chaw1/datakeel/issues)，或查看[更新日志](CHANGELOG.md)确认是否已修复。

- **Reproducible defects / 可复现的缺陷**: Use the [Bug report template](.github/ISSUE_TEMPLATE/bug_report.md) and include exact commands, version/commit, database backend (`SQLite` / `PostgreSQL`), and redacted logs.
- **Workflow improvements / 功能与流程改进**: Use the [Feature request template](.github/ISSUE_TEMPLATE/feature_request.md) describing the user problem, expected observable behavior, and acceptance criteria.
- **Usage questions / 使用疑问**: Open an issue in English or Chinese describing what you ran (`datakeel demo`, `api`, `worker`, or `mcp`) and what output or UI behavior you observed.

## Data hygiene & security / 数据脱敏与安全边界

- Never attach real credentials, API keys, personal filesystem paths, private network addresses, or real tenant/customer data to issues or screenshots. Use generated demo fixtures and reserved domains (`example.org`).
- **Suspected security vulnerabilities** must **not** be posted in public issues. Report them privately through [SECURITY.md](SECURITY.md) (<https://github.com/chaw1/datakeel/security/advisories/new>).
- **Code of Conduct violations** should be reported privately as described in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

---

- 提问与截图切勿包含真实凭证、API 密钥、本机个人路径、内网地址或真实业务/客户数据，请使用本地生成的 demo 样例和 `example.org` 等保留域名。
- **疑似安全漏洞**请勿发在公开 issue，请按 [SECURITY.md](SECURITY.md) 通过 GitHub 私密通道报告；**行为准则举报**同走 [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) 中的私密流程。
